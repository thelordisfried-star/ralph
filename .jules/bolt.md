## 2024-05-18 - Destroying Graph State by Array Recreations
**Learning:** In React Flow, when implementing custom interactions like step-by-step visibility changes (e.g. Next/Prev buttons), replacing the entire \`nodes\` and \`edges\` arrays by calling helper functions like \`getNodes()\` causes all internal React Flow state—such as node positions updated by user drag events—to be lost and overwritten. This previously forced the use of a \`useRef(nodePositions)\` to manually track positions and resulted in O(N) object allocations on every step change.
**Action:** Instead of recreating the arrays from scratch, apply functional state updates mapping over existing elements (e.g., \`setNodes(nds => nds.map(...))\`) and mutate only the specific visual properties like \`opacity\` and \`pointerEvents\`. By extracting lookup maps (like \`stepIndexMap\`, \`noteVisibilityMap\`, and \`edgeConnectionMap\`) outside the component, we achieve an O(N) bulk update with zero position-tracking overhead and no loss of user-driven state.
