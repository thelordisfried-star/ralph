## 2024-07-13 - [React Flow Functional Visibility Pattern]
**Learning:** In React Flow, rebuilding the entire node and edge arrays natively on every state update to toggle visibility forces the library to discard internal layout state (like node bounds) and forces developers to use brittle `useRef` coordinate-tracking workarounds inside `onNodesChange` just to drag elements. Additionally, `getEdgeVisibility` hallucination logic was flagged in a previous review incorrectly claiming it was used by `initialEdges`, confirming static reviews sometimes disagree with TS compilers.
**Action:** Always prefer functional state setters (e.g., `setNodes(nds => nds.map(...))`) to selectively update style attributes on existing elements. Return the original object instance unmodified if the new state evaluates to the same visibility style in order to preserve referential equality and prevent React from initiating expensive rerenders for the unaffected nodes.
