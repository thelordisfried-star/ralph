## 2024-07-16 - O(1) React Flow State Updates
**Learning:** In React Flow applications, re-creating entire node and edge arrays from scratch on every state update (e.g., inside step or timeline navigation) forces the library to discard critical internal states (like exact dimensions and node positions) and triggers massive, unnecessary re-renders. Previous workarounds, like tracking x/y coordinates via manual `useRef` maps, only hide the underlying anti-pattern.
**Action:** When animating or conditionally toggling properties of React Flow elements, embed metadata (like index markers) directly into the initial element `data` object to enable O(1) property access. Then, always use functional state updates (e.g., `setNodes(nds => nds.map(...))`) to selectively update *only* the specific style properties (like opacity) of the elements that change, returning the original unmodified object for everything else. This preserves referential equality and allows React Flow to natively maintain position and dimension states seamlessly.
