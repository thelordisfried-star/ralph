## 2024-08-21 - React Flow functional state updates mapping over existing elements
**Learning:** In a React Flow application, recreating the entire array of nodes and edges from scratch (via mapping functions inside functional state updates or event handlers) can cause O(N) object allocation overhead, leading to poor React re-render performance, particularly in interactions like pagination. Also, a manual `useRef` position tracking is often redundant and unidiomatic because React Flow's native `applyNodeChanges` automatically syncs node drag positions in the state.
**Action:** When updating node/edge state properties like visibility, use functional state updates (`setNodes(nds => nds.map(...))`). Leverage React's referential equality by returning the exact same element (`if (node.style?.opacity === opacity) return node;`) if no properties have actually changed. This prevents unnecessary React Flow DOM re-renders and eliminates manual position-syncing ref hacks. Embed static lookup metadata inside the node/edge `data` objects during initialization to enable O(1) checks.
