## 2024-05-18 - Avoid O(n²) Array Recreation in React State Update
**Learning:** In React applications like this `flowchart` tool built with `reactflow`, the functions `handleNext` and `handlePrev` perform an O(N) re-creation of all nodes and edges. While `N` is small here, it's an anti-pattern to recreate `setNodes(getNodes(...))` and `setEdges(edgeConnections.map(...))` entirely on every step change instead of updating just the required items or pre-calculating the visibility maps, but since `ReactFlow` requires the `nodes` and `edges` arrays to be updated immutably, we can improve performance by updating the objects *in place* within the array (using `.map`) rather than completely re-evaluating the `createNode` and `createEdge` functions, which recreate entire objects. Actually, better yet, `handleNext` and `handlePrev` share the exact same logic for updating state. We can extract this into a single helper, and avoid calling `getNodes` and `createEdge` on every render if we just update the specific node/edge `style` that changes.
**Action:** Extract duplicate state update logic in `handleNext` and `handlePrev` into a shared `updateVisibility(newCount)` helper to reduce code duplication and simplify maintenance. Instead of completely re-running `createNode` and `createEdge` which re-allocates all objects, we can simply map over the existing state and update only the `style.opacity`, `style.pointerEvents`, and `animated`/`label` properties based on the new count. This avoids full object recreation and preserves ReactFlow's internal node state (like dragging).
